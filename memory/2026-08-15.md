### Algorithm Builder — 3 bugs found & fixed (algorithm_builder_ui.py + engine)
1. `locked_params` vs `locked`: the UI passed the execution-lock dict to
   `build_request_signature()` under `locked_params`, but that function names the
   param `locked` (engine's `build_algorithms` calls it `locked_params`). Fixed by
   filtering shared keys and passing `locked=build_args["locked_params"]`.
2. **Real crash my new AppTest caught**: after a healthy build with an ensemble
   (the default!), rendering results called `st.code(r.code())` →
   `generate_python("ensemble", ...)` → `ARCHETYPES["ensemble"]` → **KeyError**,
   killing the whole tab. Added an ensemble branch to `generate_python` that
   rebuilds each member with its fitted params via the engine's own backtest path
   and blends equity by cumulative wealth; enriched the ensemble AlgorithmResult's
   `params` with `members_detail` (archetype/params/ops_algo/backtest_params).
3. **Latent export bug found by EXECUTING generated scripts**: `json.dumps` emits
   JSON tokens (`null`/`true`/`false`) that are invalid Python, so any downloaded
   script with `None` in backtest_params or bool strategy params (extremely
   common) NameError'd on `null` the moment it ran. compile() tests never caught
   it. New `_py_lit()` (repr-based with numpy-scalar normalization) used for all
   embedded literals. Now ALL generated script types (single, OPS, ensemble)
   compile AND run against mocked data — verified by exec.

### Quant Portal slowness — root cause & fix
`quant_ensemble_model.predict()` → `advanced_ml_engine.analyze_symbol_ensemble()`
online-trains LSTM + Transformer + MLP/RF/GBM per call. Measured: **one predict =
9.57s**; the signal-history loop ran ~110 predictions ≈ **17 minutes**.
Profile showed 3.93s of each predict was `_prepare_data` → `sec_13f_engine.
get_global_smart_money_flow()` (3.13s, called TWICE per analyze, zero caching,
returns the same aggregate every time).
Fixes:
- `sec_13f_engine.get_global_smart_money_flow` now caches its aggregate for 10
  min (class-level `_FLOW_CACHE`, same pattern as `_COMPANY_TICKERS_CACHE`).
  Helped EVERY ML caller app-wide (scanner, backtester, breaking trades...).
- `quant_portal.py` signal-history loop capped at 24 evenly-spaced windows
  (was ~110). Result: **~17 min → ~20s** (4.6s current + 14.9s history cold;
  warm clicks ~0.6s/predict).
- Also fixed Tab 1 returns-display mis-indentation (display block was nested in
  the `else:` branch → NameError on empty data, never displayed on normal data;
  and `(1+r)-1` last-day return → now true cumulative `.prod()-1`), plus
  MultiIndex-Close normalization in Tab 3 + Tab 4 (Regime Detection).
