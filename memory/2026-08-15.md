### Algorithm Builder upgrades (engine + UI)
- **5y data** default (`period="5y"`).
- **Multi-window returns**: `window_returns()` computes trailing returns of the
  equity curve over 5y/3y/2y/1y/6m/3m/1m (WINDOW_SPECS); short histories leave
  longer windows None. Stored on every AlgorithmResult, shown in UI + markdown.
- **Many backtests per algorithm**: `runs_per_family` (default 3) — each family
  is searched with distinct seeds; every run is a full backtest card labelled
  "(run x/3)". UI slider (auto + guided advanced).
- **Per-trade reasoning**: `backtest_ohlcv` trades now record `exit_reason`
  (STOP_LOSS/TAKE_PROFIT/TRAILING_STOP/MAX_HOLD/SIGNAL_FLAT/END_OF_DATA);
  `trade_narratives()` writes dynamic prose per trade (entry context: 5d drift +
  vol; why it exited; P&L; hold).
- **No-viable-strategy alerts**: failed families get `_error_result(..., suggestion=)`.
  `diagnose_failure()` profiles the data (`_data_character`: trend strength,
  lag-1 autocorr, mean-reversion index, vol) and explains WHY + concrete tweaks +
  better-suited families. UI shows an expander aggregating failures, tweaks, and
  alternatives that DID work (with metrics).
- **Dynamic ensemble** (user's new ask): `build_ensemble(method="dynamic")` —
  per-bar weights = wealth-adaptive (fast universalization) TILTED by measured
  quality (Sharpe+Sortino, drawdown cap, win rate, trade robustness) and
  penalized for redundancy (pairwise correlation). `_ensemble_rationale()` writes
  per-member strength/weakness/redundancy/weight explanation into build_notes.
  Verified: on sine data trend runs get ~67%+30%, weak mean-reversion runs ~3%+0%.
  build_algorithms defaults `ensemble_method="dynamic"`, members capped at top-6
  by OOS sharpe.
- UI: per-result window-return strip, "Trade-by-trade reasoning" expander,
  SWOT (strengths/weaknesses/unknowns) per algorithm, "Which algorithm is best?"
  comparative section (best + weakest with SWOT), failure alert expander, summary
  table gains OOS Sharpe + 5y/1y/6m columns; `to_markdown` gains windows/trades/
  notes sections; build signature includes runs_per_family.

## Session 3 (after commit 2ebab01): Algorithm Builder -> paper trading integration

User asked: allow built algorithms to be directly used in paper trading — a
"Test in paper trading" button on each algorithm that deploys it to a NEW paper
trading account or an EXISTING portfolio, always asking before overriding a
strategy already in place.

### What was built
- **`AlgorithmResult.strategy_spec()`** — serializes a built algorithm into a
  deployable spec: archetype, fitted params, backtest_params, universe,
  ops_algo, direction, metrics, window_returns, source. Self-contained.
- **`strategy_spec_to_signal(spec, df)`** — recomputes live target-exposure in
  [-1,1] from the spec on fresh OHLCV (long_only clips shorts); None for
  online_ops. **`strategy_spec_to_weights(spec, dfs)`** — portfolio-level
  rebalance weights for online_ops archetypes.
- **paper_trading_system**: `deploy_strategy(account_id, spec)` (merges into
  automation_config under strategy_spec, preserves other keys like risk rules;
  does NOT toggle automation), `get_deployed_strategy`, `remove_strategy`,
  `_set_automation_config`. Deployed strategy survives app restarts.
- **automated_trading_engine**: strategy mode. `start_automation` gains
  `strategy_spec` kwarg (falls back to whatever is deployed on the account).
  `_execute_trading_cycle` routes to `_execute_strategy_cycle` when a spec is
  deployed: per-symbol signal entries/exits sized by the backtest's risk budget
  (ATR-based, capped by risk rules); `_execute_ops_strategy_cycle` rebalances
  toward target weights for online_ops. `get_strategy_spec` accessor.
- **algorithm_builder_ui**: "Test in paper trading" button per algorithm card
  -> deploy panel: NEW account (name + balance) or EXISTING portfolio
  (selectbox). Existing with a strategy => warning + mandatory override
  checkbox; deploy button disabled until confirmed. Success message points user
  to Paper Trading tab to enable automation.
