User reported 4 issues; all fixed and committed.

### 1. qp_symbol_input widget warning
- Error: "The widget with key 'qp_symbol_input' was created with a default value but also had its value set via the Session State API."
- Root cause: `st.text_input(value=..., key=...)` + the Stocks/Futures/FX/Crypto quick-select `on_click` callbacks write `st.session_state["qp_symbol_input"]`. Streamlit's `policies.check_widget_writes` warns whenever `default_value is not None` AND the key is "new state" (set via the API).
- Fix: seed with `st.session_state.setdefault("qp_symbol_input", "AAPL, MSFT, NVDA")` BEFORE the widget and drop the `value=` param. Canonical Streamlit pattern; no more warning.
- Lesson: never pass BOTH `value=` and a `key` to a widget whose state may be written via session state (callbacks or setdefault). Use setdefault + no value=.

### 2. Advanced backtest metric accuracy (total return, Sharpe everywhere)
- Removed the RANDOM synthetic fallback (`np.random.randn`!) in the Advanced Backtesting tab that fabricated Total Return/Sharpe when the backtester returned None. Now shows an honest insufficient-data warning with the bar count.
- `final_capital` now = true cash after the end-of-period close, and `equity[-1]` is re-recorded to that value so Total Return == the plotted equity curve exactly (previously the curve kept the open position marked at raw price, ignoring exit commission).
- Sharpe/Sortino/rolling-Sharpe in AdvancedBacktester now use sample std (ddof=1) to match pandas `.std()` used everywhere else.
- `_calculate_advanced_metrics` in quant_portal now uses the standard Sharpe (mean/std*sqrt(252)) instead of the annual_return/volatility approximation; Sortino fixed (was double-annualizing — denominator was already *sqrt(252)).
- Benchmark (buy & hold) now spans the strategy's own window (bench_start=lookback-1), not the whole series — apples-to-apples alpha comparison.
