### Found & fixed
The Dark Pool feature stored alerts (5 kinds) but **never evaluated them** — the UI
even claimed "Alerts evaluate on each scan". Implemented real evaluation:

- `dark_pool_engine.py`:
  - `add_alert` now assigns a `uuid` id.
  - `_alert_key()` — uuid for new alerts, content fingerprint (`legacy:...`) for
    pre-existing state files so old sessions still evaluate + honour cooldowns.
  - `_evaluate_alert(alert, report)` — per-kind conditions with documented
    0..1 threshold semantics:
    - `offex_pctile_90` -> 5d off-ex volume pctile >= threshold*100
    - `large_print` -> modeled block vol >= threshold * 20d avg volume
    - `imbalance_threshold` -> |5d imbalance| >= threshold
    - `activity_acceleration` -> |imbalance accel| >= threshold
    - `ai_unusual` -> top signal strength >= threshold*100
  - `evaluate_alerts(reports=None)` — one `analyze_ticker(include_live=False)` per
    symbol, persisted `alert_fired` cooldown log (6h, class attr
    `ALERT_COOLDOWN_HOURS`), pruned to 7 days, errors reported not raised.
- `dark_pool_ui.py` Alerts tab: "Check alerts now" button + spinner, per-kind
  threshold help on the selectbox, honest captions (cooldown + "never places trades").
