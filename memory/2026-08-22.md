# 2026-08-22 — Tool router: outsource chat tool asks to Octavian's own engines

## Request
User: "make sure to scan prompts inputted by the user to the AI chatbot that
ask for tasks for tools already created (DCFs, Bayesian network, Markov model
etc.). Outsource the AI chatbot's work to these tools — input what the user
wants into those tools and repackage the results as the AI chatbot's work to
answer more precisely."

## What I built
New module `tool_router.py` (~450 lines). Detects explicit tool vocabulary in
user chat prompts and dispatches to the REAL engine that powers that feature,
repackaging the engine's computed output as the chatbot's answer (never an
LLM-improvised DCF/regime call).

**Tool registry (`_TOOLS`) — 10 tools:**
1. **DCF** → `financial_model_generator.InstitutionalDCFEngine`
   (`compute_wacc` / `project_fcf` / `compute_terminal_value`) from reported
   fundamentals; bear/base/bull fair values + upside + WACC + explicit
   reinvestment assumptions.
2. **Reverse DCF** → `market_consensus_engine.reverse_dcf_expectations`
   (implied revenue growth / EBIT margin / FCF growth + gap label).
3. **Bayesian network** → `institutional_analytics_engine.BayesianNetwork`
   — shock propagation (parses a named node + value, defaults to Inflation →
   80%), table of prior/posterior/Δ per node across macro/market/asset layers.
4. **Markov / HMM regime** → `hmm_engine.get_regime_detector()` fit on the
   symbol's own price history (regime + confidence + per-cluster probs).
5. **Dark pool** → `dark_pool_engine.analyze_ticker` + `ai_insight`
   (off-exchange share, imbalance, pressure, block volume).
6. **Institutional 13F** → `sec_13f_engine.get_global_smart_money_flow`
   (per-symbol net flow + top inflows/outflows; DATA UNAVAILABLE when absent).
7. **Correlation** → `risk_engine.correlation_matrix` (needs 2+ symbols).
8. **Options greeks** → `options_engine.black_scholes` (spot/strike/IV parsed
   or defaulted; all greeks incl. vanna/charm/volga).
9. **Factor crowding** → `factor_crowding_engine` `detect_crowded_trades` +
   `simulate_hf_overlap`.
10. **Market regime** → `regime.get_regime_context` (VIX + tape).

**Design rules:**
- Fires ONLY on explicit tool vocabulary. Verified no false positives on:
  "hedge my XOM position", "what options strategy for LOW", "probability of
  NVDA reaching 300" (already handled by target-probability intent),
  bare filler "hmm, what do you think?".
- `(?<!reverse )\bdcf\b` negative lookbehind so "reverse DCF" routes to the
  Reverse DCF tool only (no double valuation).
- `\bhmm\s+(?:model|regime)\b` — bare "hmm" never triggers Markov.
- Every runner fully defensive → returns None on missing data, so the normal
  pipeline is never degraded.
- Multi-tool queries run ALL matched engines and combine sections.

**Wiring (all three chat paths):**
- `financial_llm_engine.generate_financial_analysis` — after deep-dive +
  mega gates, before specialist builders; result cached like other responses.
- `financial_llm_engine._build_single_answer` — same gate per mega part.
- `ai_chatbot.OctavianEnhancedChatbot.process_query` — classic path returns
  the tool answer directly before the symbol-analysis pipeline.

Intentionally NOT routed: COT (live CFTC download could hang a chat turn).

## Notes
- The router imports engines lazily inside runners (no circular imports —
  financial_llm_engine imports tool_router at call time).
- `mocked_pipeline()` (chatbot_eval) mocks `fetch_ticker_fundamentals` /
  `data_sources.get_stock` so DCF / Markov / dark-pool runners produce
  deterministic output in eval and tests.
- Keep `tool_router.py` in sync whenever a new engine is added that should be
  reachable from chat ("outsource to tools" is a core product behavior now).
