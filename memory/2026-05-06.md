
## ToS & Auth Fixes (2026-05-06)

**Problem:** ToS was being re-prompted every session even for authenticated users. The onboarding gate was dead code (ran after `st.stop()`).

**Fixes applied:**
1. **db_manager.py**: Added `tos_accepted BOOLEAN DEFAULT 0` to `users` table. Added `ALTER TABLE` migration so existing DBs get the column without data loss.
2. **auth_engine.py**:
   - `authenticate_user()` now reads `tos_accepted` from DB and sets `session_state['tos_acknowledged']` — so logged-in users never see ToS gate again.
   - `register_user()` now takes `tos_accepted: bool` param, blocks if False, stores `1` in DB.
   - Signup form: renamed keys to avoid conflicts, clearer label, passes `tos_accepted=True`.
3. **main.py**: Fixed dead-code onboarding gate (was after `st.stop()`). Refined `_require_tos_acknowledgment` docstring to clarify it's now only a legacy fallback.
4. **terms_of_service.py**: Fully rewritten. Informational-only for accepted users. Legacy accounts get a checkbox that persists acceptance to DB immediately via `execute_query`.
5. **DB migration run**: Both existing users (`apb`, `tester`) marked `tos_accepted=1`.
