## Load-time performance pass (user: "loading speeds are atrocious, please fix this")

Profiled the Streamlit app with cProfile through AppTest (cold import + warm rerun
timing). Three real bottlenecks found and fixed:

1. **Dashboard per-rerun cost (~2.8s → ~1.6s with mocks; more with real network)**
   - `trader_profile.generate_market_aware_insights()` fetched a LIVE VIX series
     (`get_vix(period="6mo")` → stooq/yfinance fallback chain ~1.5s) on EVERY
     rerun of the landing Dashboard — completely uncached at the Streamlit layer.
   - Fix: extracted the market-state fetch (master-engine outlook + VIX) into
     `_cached_market_state()` with `@st.cache_data(ttl=300, show_spinner=False)`.

2. **`data_sources.get_realtime_prices_batch()`** was sequential per-symbol
   `yf.Ticker().fast_info` (4 index tickers = 4 serial network round-trips every
   30s fragment tick + every rerun), with debug `print()`s on every fetch.
   - Fix: parallelized with ThreadPoolExecutor (max 8), removed the debug prints,
     raised `_REALTIME_CACHE_TTL` 5s → 15s.

3. **Quant Portal first click was 8.85s** — module-level imports of the whole
   sklearn/torch/scipy chain (quant_ensemble_model, advanced_backtester,
   genetic_strategy_engine, macro_cross_asset_engine, alternative_data_engine,
   risk_engine) at import time.
   - Fix: converted to lazy availability flags via `importlib.util.find_spec`
     (`HAS_*`) + imports at point of use inside `render_quant_portal()`.
     Incremental import: 8.85s → 0.47s (18x). First-nav AppTest: 3.0s → 1.7s.

Notes / measurements:
- `data_sources` cold import ~9s (yfinance 2.2 + pandas 3.9 + streamlit 2 +
  config→streamlit) — one-time per process, cached in sys.modules, not the
  recurring complaint.
- Dark Pool Intelligence first-nav 12.8s is the real market scan
  (`scan_market` → per-ticker analysis) — cached 15 min afterward (warm 1.8s);
  legitimate page work, left alone.
- Financial Model Generator 5.7s first-nav is mostly the 7-tab render +

- Test changes: 3 walkthrough tests patched `quant_portal.get_stock` (module
  attr no longer exists) → now patch `data_sources.get_stock` (the lazy
  call-site source). Full suite: **758 passed** (was 758, no count change).

## Market whispers datetime fix + counter-trend upgrade (user: "fix this: Error loading market whispers" + "update and improve the counter-trend signals")

**Bug**: "Error loading market whispers: can't compare offset-naive and offset-aware
datetimes". Root cause: RSS dates parsed with `email.utils.parsedate_to_datetime`
are timezone-AWARE, but the whisper/news code compared them against naive
`datetime.min` / `datetime.now()` in sort keys and the recency cutoff
(`get_market_whispers`, `get_news_summary_for_symbol`, `_get_recent_articles`).

Fix: module-level `_naive_utc()` in `news_analysis_engine.py` normalizes any
datetime to naive UTC (aware → astimezone(utc).replace(tzinfo=None); naive →
as-is; None → None). Applied to all whisper/news sort keys + the recency cutoff.

**Counter-trend analyzer upgrade** (`counter_trend_analyzer.py`):
- `CounterTrendSignal` new live-price fields (defaults, backward-compatible):
  `momentum_state` (REVERSING/DECELERATING/STALLING/TREND_ACCELERATING/NO_DATA),
  `momentum_score` (−100..+100, +ve = price moving in fade direction),
  `price_confirmation`, `live_price`, `entry_condition`.
- `apply_momentum_filter(signals, price_data)` — the docstring always promised
  a momentum filter that never existed. Now: REVERSING boosted (+8), DECELERATING
  +4, STALLING entry-condition, TREND_ACCELERATING down-weighted (−0.8×|score|,
  −15 confidence) with "wait for stall" entry condition; signals with daily slope
  ≥ 3%/day (falling_knife_cutoff default 0.03) dropped outright. Accepts
  DataFrame-with-Close or float lists; missing data degrades to NO_DATA.
- `refresh_from_market_data(market_data)` — adjusts seeded consensus/fundamental
  scores from live vix / us_10y_yield / usd_index / gold_price / usdjpy /
  oil_price / smh_price (clamped 5–95), returns updated themes.
- IMPORTANT BUG CAUGHT: `__init__` aliased the module-level `_DEFAULT_NARRATIVES`,
  so in-place refreshes mutated the shared defaults and leaked state across
  instances — fixed with `copy.deepcopy` (test caught it: refresh-empty noop
  saw scores already changed by another test).

UI (`main.py` Intelligence Center): "Confirm with live price momentum" checkbox
(default ON), cached price fetch `_fetch_ct_price_data` (`@st.cache_data` ttl=600,
`get_stock(period="3mo")`), momentum badge on signal cards, entry condition +
live price read shown. Import of counter_trend_analyzer moved to module top of
main.py (was inside try block).

Tests: new `tests/test_counter_trend_and_whispers.py` (15 tests) — naive/aware
whisper sorting, recency cutoff, news summary, momentum states, falling-knife
drop, refresh scoring, singleton, legacy API stability.
Full suite: **773 passed** (was 758). Intelligence Center AppTest walkthrough
passes with the new checkbox.
